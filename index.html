01

Automated Snapshot Replication & DR Retention

Designed and implemented an event-driven disaster recovery automation workflow to create volume snapshots at 30-minute intervals, transfer them to a designated DR region, and enforce a controlled retention policy. The solution was implemented across AWS and Oracle Cloud Infrastructure (OCI), using each platform’s native serverless and messaging services.

Workflow architecture

1 · ScheduleA scheduled trigger initiates snapshot creation every 30 minutes.
2 · CaptureA serverless function creates snapshots for the configured source volumes.
3 · Queue & copySnapshot tasks enter a queue; a worker function processes them and copies snapshots to the DR region.
4 · RetainRetention logic keeps the latest two DR copies per volume and removes older copies.

Cloud services used

AWS implementation

Amazon EventBridge Scheduler · AWS Lambda · Amazon SQS · EBS Snapshots · Cross-Region Copy

OCI implementation

OCI scheduling trigger · OCI Functions · OCI Queue · Block Volume Backups · Cross-Region Copy

Operational value: Reduced manual effort in recurring DR snapshot operations, separated snapshot creation from asynchronous copy processing, and applied a consistent two-copy-per-volume retention policy in the DR region. Queue-based processing also provides a clear point to monitor task status and handle unsuccessful copy operations.

Centralized Cloud Log Collection & SIEM Integration

Developed an automation script at NCS Technologies to collect logs from multiple AWS security and infrastructure services and deliver them to a centralized Security Information and Event Management (SIEM) platform. The collection covered Web Application Firewall (WAF) activity, S3 bucket logs, CloudWatch logs, and AWS Lambda logs, helping bring operational and security telemetry together for centralized analysis.

Collection workflow

1 · Identify sourcesGather log data from WAF, S3, CloudWatch, and Lambda services.
2 · CollectUse a custom automation script to retrieve logs from the configured sources.
3 · TransferMove the collected log data through the integration workflow to the SIEM platform.
4 · CentralizeMake the service logs available in one place for security and operational analysis.

Log sources & integration
